# 한창구 세부 설명

README에서 옮긴 설명입니다. 평가 숫자와 세부는 [EVALUATION.md](EVALUATION.md), 요구사항과 설계 결정은 [PRD.md](PRD.md), 데이터 규칙은 [data/README.md](../data/README.md)에 있습니다.

## 직원이 이렇게 씁니다

1. **통합 목록을 엽니다.** 어느 창구로 왔든 한 목록에 모입니다. 맨 위는 의료진에게 넘길 문의, 그 아래는 예약금을 받고 확정 연락을 아직 못 한 문의입니다.
2. **문의를 눌러 초안을 봅니다.** 문장마다 어느 안내문에서 왔는지 번호가 붙습니다. 증상·약 문의는 '의료진 인계' 카드가 먼저 뜨고, 그 안의 AI 초안은 의료진이 확인해야 보낼 수 있습니다.
3. **고치고 '승인'을 누른 뒤 보냅니다.** 승인해야 보내기 버튼이 켜집니다. 시연에서는 실제로 보내지 않습니다. 어떤 역할(CS 직원 등)이 어떤 문장을 고쳤는지 기록이 남습니다.

## 요약

### 할 수 있는 것

- **흩어진 문의를 한 목록에.** 10개 창구의 문의를 급한 순서로 보여 줍니다. 확정 연락 시한이 지난 건은 "지남"으로 표시합니다.
  - 창구: 카카오 채널, 네이버 톡톡, 인스타그램 DM, 홈페이지 상담 폼, 모발이식 상담 신청 폼, 네이버 예약 요청사항, 전화 메모, 업무용 문자, 플레이스 리뷰, 유튜브 댓글
- **병원 안내문으로 답장 초안.** 가격, 수술 후 관리, 예약 변경 규정처럼 안내문에 있는 답을 찾아 옮깁니다. 금액은 AI가 쓰지 않고 가격표에서 넣습니다.
- **증상·약 문의는 의료진에게.** "수술 9일째인데 고름이 나와요" 같은 문의는 걸린 규칙, 담당자, 응답 시한, 직원이 보낼 정해진 문구를 카드로 보여 주고, 의료진 확인용 AI 초안을 붙입니다. 초안은 [환자가 쓴 내용을 판단 없이 되짚는 한 문장(선택)] + [인계 절차의 승인 안내 문장(필수)] + [문의에 섞인 예약·가격 같은 물음의 답(병원 문서 인용)] + [문서의 연락·내원 절차 안내]로 됩니다. 되짚기 말고는 병원 문서 문장을 글자 그대로 옮겨야 하고(승인 문구는 앞뒤 말 없이), 되짚기 문장은 문의에 있는 말만·부정 말 그대로·약·판단·지시·허락 말 없이 써야 합니다. 어기면 코드가 보류하고, 직원은 이 초안을 보낼 수 없습니다(의료진 확인은 역할을 고르는 모의 확인).
- **직원 내부 질문에도 답.** "수술 3일째 환자가 머리를 감아도 되나요?"처럼 안내문에 적힌 내용을 묻는 직원 질문에 같은 안내문으로 답합니다(사내 Q&A).
- **공개 리뷰·댓글에는 정해진 문구만.** 치료 내용이나 환자임을 드러내지 않는 문구만 제안합니다.

### 믿을 수 있게 만든 장치

- **규칙이 AI보다 먼저 확인합니다.** 증상·약 단어 목록은 병원 문서에 있습니다. 이 단어가 보이면 AI보다 먼저 인계로 정하고, AI는 의료진 확인용 초안만 씁니다. 목록 문서가 비었거나 읽을 수 없으면 화면과 녹화가 멈추고 AI를 부르지 않습니다.
- **근거를 코드가 한 번 더 대조합니다.** AI가 붙인 인용이 안내문 원문과 다르거나, 문장 속 숫자·기간이 원문에 없으면 초안을 내지 않습니다. 이때 화면에 '보류'가 뜨고, 그 문의는 직원이 직접 답합니다.
- **보내는 건 사람입니다.** 자동 발송이 없습니다. 환자가 AI와 직접 대화하지 않습니다. 증상·약 문의 초안은 의료진이 확인한 뒤에만 보낼 수 있습니다.

### 아직 아닌 것

1. **실제 병원에서 써 본 적이 없습니다.** 의원은 가상이고 문의는 지어냈습니다. 카카오 등 실제 창구와 연결하지 않았고, 로그인도 없습니다.
2. **뜻이 뒤집힌 문장은 못 잡습니다.** "해도 됩니다"와 "하면 안 됩니다"는 겹치는 글자가 많아 대조를 통과할 수 있습니다. 그래서 직원이 보내기 전에 꼭 읽어야 합니다.
3. **시험 문제와 채점을 사람이 아직 확인하지 않았습니다.** 평가용 질문 50개와 각 질문의 정답 문단, 자동 테스트의 기대값은 AI가 쓴 초안입니다. 초안이 좋은지도 AI(Claude Code)가 먼저 읽었을 뿐입니다. 다음 단계는 제가 이것들을 검수하는 것입니다.

### 우리 병원에 쓰려면

도입 전에 병원이 정하거나 준비할 것입니다.

- **안내문 정리와 의료진 검토.** 시연 속 안내문 22편(가격표, 수술 후 관리, 예약 규정 등)은 AI가 쓴 가상 예시이고, 의료진 검토를 받지 않았습니다. 어떤 문의를 넘길지 정하는 증상·약 단어 목록도 이 문서에 있어서, 의료진이 확정해야 합니다.
- **환자 동의와 고지.** 이름·전화번호·이메일 등은 AI에 보내기 전에 가립니다. 하지만 증상 같은 건강 정보는 외부 AI 서비스로 나갑니다. 2026-09-30부터는 증상·약 문의 본문도 가림 뒤 의료진 확인용 초안을 위해 외부 AI(Anthropic)로 나갑니다(지금은 가상 데이터라 실제 환자 정보가 없습니다). 실제 병원 도입 시 민감정보 처리 위탁·고지·동의가 필요하고, 국외 이전 고지와 보관 정책도 먼저입니다. AI가 관여한 글을 환자에게 어떻게 알릴지도 정해야 합니다.
- **창구 연결.** 카카오 등 실제 창구와 잇는 부분은 아직 없습니다. 병원이 쓰는 상담 서비스를 본 뒤 정해야 합니다.
- **규칙 값 확인.** 예약금 '1영업일 안 확정 연락'을 "다음 진료일 진료 종료까지"로 읽었습니다(토요일 포함, 공휴일 미반영). 평일만 센다면 시연에서 '시한 지남'인 1건은 아직 9시간 남은 건입니다.
- **AI 이용료.** 초안 1건에 평균 약 $0.012, 분류 1건에 약 $0.004였습니다(건당 2센트 미만, 시연용 AI 답을 네 번째로 만들 때 잰 값). 서버·창구 연결 비용은 재지 않았습니다.

**누가 만들었나.** 조사·문서·데이터·코드 초안은 AI 코딩 도구(Claude Code)가 썼습니다. 아이디어와 채택 결정, 최종 책임은 제게 있습니다(GitHub [Min-heee](https://github.com/Min-heee)).

## 왜 만들었나

동네 의원도 문의 창구가 많습니다. 메신저 여러 개, 홈페이지 폼, 예약 요청사항, 전화·문자, 공개 리뷰와 영상 댓글.
수술 뒤 오래 관리하는 진료는 같은 환자가 여러 창구로 여러 번 묻습니다.
그래서 세 가지 문제가 생긴다고 봤습니다. 현장에서 확인하지 않은 추론이라, 병원 실무자께 맞는지 확인받고 싶습니다.

1. **놓친다.** 창구를 따로 열어야 해서, 주말에 쌓인 문의 중 무엇이 먼저인지 모릅니다. 예약금을 받고 확정 연락을 못 한 건은 돈과 평판에 바로 닿습니다.
2. **같은 답을 매번 새로 쓴다.** 수술 후 관리, 가격, 예약 변경 규정은 병원 문서에 이미 있습니다. 사람이 찾아서 옮겨 적습니다.
3. **답하면 안 되는 문의가 섞여 있다.** "수술 9일째인데 고름이 나와요", "약을 두 알 먹어도 돼요?"에 비의료인이 답하면 위험합니다.

메신저를 한곳에 받는 일은 이미 나와 있는 상담 서비스가 잘합니다. 한창구는 그걸 대신하지 않습니다.
그 서비스로 받은 문의에 예약 요청사항·폼·리뷰·댓글을 더해, **직원이 보는 화면을 하나로** 만듭니다.
그 위에 병원 규칙을 얹습니다.

## 지키는 원칙

1. **규칙이 AI보다 먼저.** 증상·약 규칙이 AI보다 먼저 돌아 인계를 정합니다. 그 뒤 AI는 의료진 확인용 초안만 쓰고, 규칙이 건 인계를 풀 수 없습니다. AI 분류는 '넘기는' 쪽으로만 바꿀 수 있습니다.
2. **깨지면 멈춘다.** 규칙 목록이 비거나 깨지면 부분적으로 돌지 않고 화면 번들·녹화가 멈춥니다. 초안이 나가지 않고 AI를 부르지 않습니다. AI 분류가 실패하면 초안을 만들지 않습니다.
3. **승인 문서만 근거.** 병원이 쓰기로 확정한 최신판 문서만 씁니다. 인용·숫자가 원문과 어긋나면 초안 전체를 멈춥니다. 금액은 AI가 쓰지 않습니다.
4. **공개 창구는 고정 문구만.** 리뷰·댓글에는 치료 내용과 환자임을 드러내지 않는 문구만 제안합니다.
5. **보내는 건 사람.** 자동 발송은 없습니다. 증상·약 문의 초안은 의료진 확인 뒤에만 보냅니다. 효과 보장 같은 광고 표현은 경고로 표시합니다.

- README의 화면 사진(`docs/screens/`)은 3회차 녹화로 `next start`를 띄워 `/`, `/inquiry/Q02`, `/inquiry/Q06`을 찍은 것입니다. 사진 속 Q02 초안 글은 4회차 녹화와 같습니다. Q06 사진은 의료진 확인용 초안이 생기기 전 화면이라 인계 카드만 보입니다.

## 실행 방법 세부

Node `^20.19 || ^22.13 || >=24`.

```bash
npm install
npm run dev              # http://localhost:3000 — 시작 전에 번들을 새로 만든다
npm test                 # 테스트 667개(664 통과, 녹화 상태에 따라 3개 건너뜀)
npm run eval:retrieval   # 검색 적중률(키 필요 없음)
npm run verify           # test + typecheck + lint + build
```

- API 키 없이 돌아갑니다. 공개 배포(https://hanchanggu.vercel.app)에도 키를 두지 않습니다 — 방문자는 녹화만 보므로 시연 비용은 0입니다.
- `verify` 안의 `next build`는 `npm run dev`와 같은 `.next` 폴더를 씁니다. 개발 서버를 켠 채 돌리면 개발 서버가 깨지니 먼저 끄세요.

**번들.** 화면은 서버 없이 브라우저에서 규칙과 검색을 돌립니다.

- `npm run bundle`이 `vault/`, `data/`, 있으면 녹화 파일을 `src/generated/bundle.json` 하나로 묶습니다. `dev`·`build` 앞에서 자동으로 돌아갑니다.
- 볼트가 깨져 있으면(적신호 목록이 비는 등) 번들을 만들지 않고 멈춥니다. 생성물은 커밋하지 않습니다.

**AI 초안 녹화(키가 있을 때만).** 방문자는 미리 녹화한 응답만 봅니다. 방문자 비용은 0이고, 공개 배포에는 키를 두지 않습니다.

```bash
cp .env.example .env.local        # ANTHROPIC_API_KEY를 직접 채운다. 커밋되지 않는다
npx tsx --env-file=.env.local scripts/record-demo.ts --all --limit 3   # 먼저 몇 건만, 비용 확인
npx tsx --env-file=.env.local scripts/record-demo.ts --all             # 전부 → data/demo-responses.json(기존 파일을 덮어씀)
npm run bundle                    # 화면에 반영
```

증상·약 문의의 의료진 확인용 초안만 녹화해 기존 파일에 합치기(기존 일반 초안·수치는 그대로):

```bash
npx tsx scripts/record-demo.ts --handover-only --dry-run                             # 키 없이 대상 문의(20건)와 추정 비용만
npx tsx --env-file=.env.local scripts/record-demo.ts --handover-only --limit 3        # 아직 녹화 안 된 대상 중 앞 3건(약 $0.05)
npx tsx --env-file=.env.local scripts/record-demo.ts --handover-only                  # 아직 녹화 안 된 나머지(이미 녹화된 건은 건너뜀, 20건 전부면 약 $0.3)
npx tsx --env-file=.env.local scripts/record-demo.ts --handover-only --only Q06,Q11   # 골라서 다시(이미 녹화됐어도)
npx tsx scripts/record-demo.ts --handover-only --redo --dry-run                      # 키 없이 다시 녹화할 대상(20건)과 추정 비용만
npx tsx --env-file=.env.local scripts/record-demo.ts --handover-only --redo           # 대상 전부 다시(지시문·발췌를 바꾼 뒤, 약 $0.3~$0.44)
npm run bundle                    # 그 뒤 git diff data/demo-responses.json이 인계 초안 칸·handoverRun만 바뀌었는지 확인
```

- 무엇을 녹화할지 반드시 고릅니다(`--all` 또는 `--handover-only`). 모르는 인자는 거부합니다 — 오타 하나로 전체 재녹화(4회차 파일·수치를 덮어씀)가 돌지 않게.
- 대상은 지금 규칙이 인계로 보내거나 기존 녹화의 분류가 인계로 보낸 문의 중 공개·모르는·쇼핑몰 창구가 아닌 것입니다(분류는 다시 부르지 않음). `--only`·`--redo`가 없으면 이미 인계 초안이 녹화된 문의는 건너뜁니다. 기존 파일이 없거나, 모양이 틀리거나, 볼트 기준일이 다르거나, 대상의 기존 기록이 인계 경로가 아니면 키를 읽기 전에 멈춥니다.
- 합칠 때는 파일 원본에 문의별 `handoverDraft`와 최상위 `handoverRun`(인계 녹화 사용량)만 더합니다(다시 녹화하면 그 문의의 `handoverDraft`를 바꾸고, `handoverRun` 사용량은 지금까지 쓴 양을 계속 더합니다). 한 건 녹화할 때마다 합쳐 파일에 써서, 중간에 멈춰도 이미 쓴 크레딧의 결과가 남습니다. 일시 오류가 난 건은 합치지 않고 다시 녹화할 `--only` 목록을 찍습니다.
- 번들을 만들 때 인계 초안이 빠진 건이 있으면 "경고: 인계 초안 녹화 전 N건"만 찍고 빌드는 멈추지 않습니다.

- `npm run record-demo -- --all`처럼 npm으로 부를 때도 `.env.local`을 스스로 읽지 않습니다. 위처럼 `--env-file`로 넘기거나 환경변수로 줍니다.
- 녹화 뒤 볼트나 규칙이 바뀌면 해당 건에 "AI 답 이후 바뀜"이 표시됩니다.
- 공개 배포(production)와 CI는 녹화 파일이 없으면 빌드를 멈춥니다. 초안 장면이 빈 링크가 나가지 않게 하려고서입니다.
- 녹화 없이 '녹화가 있을 때' 화면을 보려면 `DEMO_FAKE_RECORDING=1 npm run dev`. 모델을 부르지 않는 시험용 가짜 답이고, 화면에 그렇게 표시됩니다. 빌드·배포에서는 막힙니다.
- 2회차 녹화는 다시 채우기 시험용 사본으로 `src/demo/__fixtures__/recording-round2.json`에 둡니다(3430ae2의 `data/demo-responses.json`과 같은 바이트).

## 처리 경로

```
문의 → 가림 → 규칙 게이트 ─┬─ 의료진 인계 카드 ─(공개·모르는·쇼핑몰 창구가 아니면) 인계 발췌 → ③생성 → ④근거·검증 → 의료진 확인(모의) 뒤 발송
                         ├─ 공개 창구 → 고정 문구
                         └─ 분류 → 경과일 → ①검색 → ②발췌 → ③생성 → ④근거·검증 → 직원 승인
```

- **가림.** 전화·이메일·주민번호·생년월일·호칭·폼의 이름·주소를 모델 호출 전에 가립니다. 모델이 받을 글을 화면에서 볼 수 있습니다.
- **규칙 게이트.** 적신호 단어·경과 문맥·약 관련 표현을 볼트 문서에서 읽어 모델보다 먼저 돌립니다. 목록은 코드에 없고 문서에 있습니다. 걸리면 인계 카드(걸린 규칙, 담당, 응답 시한, 직원이 환자에게 보낼 승인 문구)로 갑니다.
- **인계 초안(의료진 확인용, 2026-09-30 오너 결정, 같은 날 두 번째 결정으로 문의 맞춤 허용).** 인계 카드 안에 AI 답장 초안을 붙입니다. 공개 창구(리뷰·댓글), 모르는 창구, 쇼핑몰 창구에는 만들지 않습니다.
  - 구성: [되짚기 0~1문장] + [승인 안내 문장(필수)] + [문의에 섞인 의료가 아닌 물음의 답(있을 때만)] + [연락·내원 절차 안내(문의와 이어질 때만)]. 예: "수술 9일째 이식 부위에서 고름이 나온다고 말씀 주셨습니다. (V12 승인 안내 세 문장)". 진단·원인 추정·정상 여부 판단·치료 지시·약 이름·용량은 어느 문장에도 쓰지 않게 합니다.
  - 발췌는 코드가 고른 문단만 보냅니다. 인계 절차(V12)의 '환자에게 보내는 고정 안내 문장' 문단이 맨 앞, 적신호 기준(V11)의 즉시 조치 문단('문맥 없이도 인계하는 증상' — 119·응급실 안내)이 그다음입니다. 문의의 **물음 절**(물음표·"…나요/까요/죠"·"…는지도 물음"·"알려 주세요"가 있는 문장의 마지막 절)에 의료가 아닌 물음의 말(얼마·가격·예약·변경·취소·시간·주차·반품·주문 등)이 있을 때만, 행정 안내 문단(진료시간·오시는 길 V02, 가격표 V03, 예약 규정 V04, 쇼핑몰 문의 안내 V18) 중 BM25 점수가 근거 약함 기준(9) 이상인 것을 최대 2칸 붙입니다. 그다음 수술 후 관리(V07)의 즉시 조치 문단('수술 당일 밤'·'이상하면 연락') 중 약 말이 없는 것을 붙입니다(모두 합쳐 5칸까지). 지금 문의 20건 중 행정 안내 문단이 붙는 것은 Q21(두피 관리 얼마)·Q36(경과 진료 시간)·Q40(반품)뿐입니다.
  - 행정 안내 문서에서도 변경 이력·원칙·'가격을 물으면'·효과·증상·직원·공개 창구·수술 후 일정 절, '직원'이 든 문단(직원 처리 순서), 응답이 늦어진다는 문단(점심시간 "순서대로 답합니다", 휴진 "순서대로 확인합니다", 쇼핑몰 "병원 창구에서 답하지 않고" — 승인 문구의 "바로 전달했습니다"와 부딪침), 약·증상 말이 든 문단은 보내지 않습니다. 고르지 않은 문서: 수술 후 날짜별 관리(V07의 날짜별 관리 지시), 약 원칙(V17), 적신호 목록(V11의 증상 목록), 수술 전 안내(V06 — 약·음주 지시), 두피 주사·두피 관리(V08·V09), 첫 상담 안내(V05 — '감기 기운이 있어도 상담은 받을 수 있다'가 '병원에 와야 하는지'의 답이 됨). 인용 허용 문서도 인계 문서(V07·V11·V12·V17)와 이 행정 안내 문서(V02·V03·V04·V18)로 맞췄습니다.
  - 직원 절차 문단(누구에게·몇 분 안에·무엇을 기록하나, V17 '직원이 하는 일' 등)과 날짜별 일반 관리 문단은 보내지 않고, 경과일 앞세우기도 하지 않습니다. V11이 "증상이 적힌 문의에는 [수술 후 관리 문서]로 답하지 않습니다"라고 적기 때문입니다. 약 원칙(V17)은 인용 허용 문서지만, 지금 볼트에서는 문단마다 약 말이나 직원 절차가 있어 보내는 문단이 없습니다.
  - 지시문에는 인계 초안에만 규칙 16~19를 더했습니다. 위 구성 순서, 되짚기 한 문장의 형식(맨 앞·문의의 낱말 그대로·"…라고 말씀 주셨습니다"로 끝냄·물음은 "…는지 문의 주셨습니다"로만·부정 말 그대로·증상은 모두·약 이름·용량·금액·판단·권유·지시 없음), 승인 안내 문장은 따옴표 없이 앞뒤 말 없이 한 글자도 바꾸지 말고 통째로, 섞인 의료가 아닌 물음은 그 물음에 답하는 문서 문장을 글자 그대로 인용(금액은 가격 칸으로만, 진료시간은 "진료시간은 {{hours}}입니다." 한 문장, 이음말은 "또한"·"그리고"뿐, 링크 문장 금지), 직원 절차 문장은 인용하지 않기입니다. 일반 초안 규칙 중 '의료진이 판단한다' 문장을 인용하라는 부분(규칙 4의 둘째 문장, 규칙 12의 예외)과 '물음 하나라도 답이 없으면 [근거 없음]'(규칙 2·13)은 인계 초안에서 끕니다. 답장·사내 Q&A 지시문은 바이트까지 그대로입니다(4회차 녹화와 어긋나지 않게 — 머리말까지 전체를 스냅숏으로 고정).
  - 일반 초안과 같은 인용 대조·숫자 대조·가격 칸 대조·광고 검사를 거친 뒤 코드(`src/llm/handover-check.ts`)가 문장을 한 번 더 봅니다. 다음이면 보류합니다.
    - 승인 문구 세 문장이 통째로 들어 있지 않음, 고정 안내 문단을 인용한 문장에 승인 문구 밖 글자가 하나라도 있음(따옴표 밖 "인계한 뒤 환자에게는 다음 문장만 보냅니다", "아니요, "·" 기다려 보세요." 같은 머리·꼬리), '직원'이 든 문장이 있음.
    - 되짚기가 아닌 문장이 인용 원문 문장을 공백·문장부호만 빼고 글자 그대로 옮기지 않음(바꿔 쓰기·줄이기·말 끼우기). 예외는 금액 자리의 가격 칸, 앞에 붙인 "또한"·"그리고", 진료시간 문장 하나뿐입니다. 인용 없는 자리표시자 문장("바로 오시면 되는 시간은 {{hours}}입니다.")도 받지 않습니다.
    - 되짚기 문장(인용 없이 받는 유일한 문장): 맨 앞이 아니거나 둘 이상, 확인 어미로 끝나지 않음, 판단·권유·지시·허락 말(괜찮·정상·원인·때문·하세요·복용·된다고·해도 된·먹어도 등)이 있음, 약 말(문의에 있어도)·용량(500mg·두 알)·금액이 있음, 숫자·증상 말·내용어가 가림 뒤 문의에 없음, 문의의 적신호 증상을 빼거나 그 밖의 증상 일부만 되짚음, 부정 말(안·않·못·없)을 더하거나 빼 뜻을 뒤집음("피가 안 멈춰요" → "피가 멈춘다고"), 물음 절에만 있는 말을 "…는지 문의 주셨습니다" 꼴이 아니게 되짚음("헬스장 가도 된다고").
    - 되짚기·승인 문구 밖 문장에 약 말(V17 목록)·증상 말(V11 목록)·판단·지시 말(괜찮·정상·원인·때문·흔하·세요·해야 등)이 있음, 문서 링크가 든 문장(가격표 문단 끝 "관리 내용은 [두피 관리 문서]를 봅니다" 등), 가격 칸 밖에 숫자로 쓴 금액.
    - 인계 문서 묶음 밖 문서를 인용함, 가격 칸 키가 인용한 가격표 문장의 금액과 다름. 근거 약함 관문은 걸지 않습니다(고정 안내 문단이 늘 들어가서).
  - 화면은 녹화 때의 통과 여부를 믿지 않고 지금 규칙으로 다시 검사합니다. 녹화 뒤 규칙을 조여 지금 검사로 보류면 발송 패널을 숨기고 사유를 보입니다(평가의 '인계 초안 검증 통과'도 같은 값을 셉니다).
  - 승인 문구를 감싼 따옴표는 보낼 글·화면 글에서 코드가 뺍니다(1차 녹화 20건 중 14건이 감쌈). 녹화 파일은 고치지 않고, 초안 검사와 화면 표시 단계에서 뺍니다.
  - 코드가 못 막는 것: 글자 그대로 옮긴 문서 문장이 이 문의에 맞는 답인지(예: 수술 후 경과 진료 일정을 묻는 Q36에 예약금이 있는 일반 예약의 변경 규정을 옮기는 것), 문의의 말을 순서·수식 관계만 바꿔 다시 엮은 되짚기. 그래서 의료진이 문장마다 확인해야 보냅니다.
  - 직원은 보낼 수 없습니다. 의료진(간호사·의사) 역할로 '의료진 확인(모의)'을 누른 기록이 있어야 발송 버튼이 켜지고, 보내는 사람도 의료진 역할이어야 합니다. 확인 뒤 글을 고치면 다시 막히고, 글을 고쳐 저장하는 것도 의료진 역할만 합니다. 역할은 로그인 없이 드롭다운에서 고르는 모의 확인입니다.
  - 인계 초안을 보내도 목록의 '인계' 상태·묶음·요약·시한 경보는 그대로이고 '인계 초안 보냄' 표시만 붙습니다. 보낸 글은 "의료진이 확인한 뒤 직접 연락드리겠습니다"라는 약속이지 연락을 마친 것이 아니라서입니다(V12 '인계한 뒤'). 직원이 보낼 초안과 다른 칸에 저장해서 평가 숫자(오보류 0/39 등)에 섞이지 않습니다.
- **사내 Q&A 규칙 카드.** 직원 질문에 적신호·약 말이 있으면 AI 답과 상관없이 결과 맨 위에 카드를 띄웁니다. 인계 절차 문서의 '누구에게'·'몇 분 안에' 문단(약 문의만 걸리면 분 시한이 적신호 기준이라 '언제 인계하나'·'누구에게' 문단)을 그대로 옮겨 보이고, AI 답은 그 아래에 둡니다(3회차 녹화 G46 답에 '5분 안에 인계'가 빠져서 넣었습니다). 함께 지시문에 규칙 15(증상·약 직원 질문이면 인계 절차 문장을 통째로 인용)를 더했고, 4회차 녹화의 G46 AI 답은 '5분 안에 인계' 문장을 인용합니다.
- **분류.** 유형과 우선순위를 Claude 구조화 출력으로 받습니다. 실패하면 초안을 만들지 않고 보류합니다(녹화 때 규칙 게이트를 통과한 문의 20건을 실제 모델로 분류).
- **경과일.** "열흘째", "D+7", "3주 됐는데"를 숫자로 읽어 그 시기의 안내 문단을 검색 결과 앞에 둡니다. 직원이 값을 고칠 수 있습니다.
- **①검색·②발췌.** 한국어 문자 2-gram BM25로 문단을 찾습니다.
  - 승인된 최신판만 대상입니다. 옛 판과 초안 문서는 "제외됨"으로 보입니다.
  - 최고 점수가 기준(9) 미만이면 모델을 부르지 않고 보류합니다.
  - 순위를 돕는 규칙은 순위만 바꿉니다. 환자 말을 문서 말로 넓히기, 소제목 끝 괄호에 적은 찾는 말, 직원 질문의 적신호·약·인계 절차 문단 앞세우기, 날짜 세는 기준 문단 함께 보내기입니다.
  - 보류 판정은 이 규칙들을 모두 뺀 점수로 합니다. 규칙 때문에 근거 없는 질문이 '근거 있음'으로 바뀌지 않게 하려는 것입니다.
- **③생성·④근거.** Claude API의 문서 인용(citations) 기능으로 초안을 받습니다. 인용 원문이 볼트 문단과 같은지, 문장 속 숫자·기간이 인용 원문에 있는지 코드가 대조합니다. 하나라도 어긋나면 초안 전체를 보류합니다.
- **가격 칸.** 모델에는 금액을 주지 않습니다. 모델은 자리표시자만 쓰고, 코드가 가격표 문서에서 값을 넣습니다.
- **승인.** 직원이 고치고 승인해야 (모의) 발송 버튼이 켜집니다. 어떤 역할(검토자가 직접 고름)이 어떤 문장을 고쳤는지가 브라우저에 남습니다. 인계 초안은 직원 승인이 아니라 의료진 확인 기록으로만 켜집니다.

임베딩 대신 BM25를 고른 이유: 문서 22편·문단 150개 안팎 규모이고, "D+3"처럼 글자가 정확히 맞아야 하는 용어가 많고, 왜 그 문단이 나왔는지 사람이 설명할 수 있어서입니다. 문서가 수천 편으로 늘면 임베딩을 섞습니다.

## 한계 세부

- **초안 품질 판정은 AI 1차뿐입니다.** 문장 단위 판정은 4회차 46건(2회차 45건도)에 대한 Claude Code의 1차 판정이고, 제가 아직 검토하지 않았습니다. 3회차는 전수 검토를 하지 않았습니다. 분류 정확도와 응답 시간은 재지 않았습니다.
- **검색이 정답 문단을 놓치면 답할 수 있는 질문도 보류됩니다.**
  - 2회차 녹화의 오보류 3건과 Q33은 문의와 정답 문단의 말이 달라서였습니다(예: 문의는 "바꾸고", 문서는 "변경").
  - 볼트에 넓히기 말 목록(예약 규정 문서의 기계가 읽는 값)과 소제목 끝의 찾는 말 괄호를 더해 지금은 정답 문단이 상위 5에 듭니다. 다만 이 목록은 합성 문의를 보고 만든 것이라 다른 표현은 여전히 놓칩니다.
  - 이 규칙들은 순위만 바꾸고 근거 약함 판정에는 쓰지 않습니다. 넣었을 때 "카드 할부 개월 수 바꿀 수 있어요?" 같은 근거 없는 질문의 점수가 두 배 넘게 올라 검색 단계 보류가 풀리는 것을 적대 검증에서 확인했기 때문입니다.
- **물음 하나라도 근거가 없으면 초안 전체를 보류합니다.** 그래서 4회차에서 Q38·Q39·Q41은 초안이 없습니다. 이 가운데 Q38·Q41은 답할 수 있는 부분이 있어 지나친 보류로 봅니다([EVALUATION.md](EVALUATION.md) '4회차에서 달라진 것').
- **의료진 확인용 인계 초안은 2차 녹화에서 15 / 20이 통과했고, 사람이 아직 읽지 않았습니다.** 1차 녹화(첫 판 지시문)는 20건 모두 승인 안내 문장과 글자까지 같았습니다. 2차 녹화는 통과 15건 중 11건이 되짚기를 쓰고 2건이 섞인 물음에 답해 13건이 서로 다른 글이었고, 5건은 되짚기·인용 검사로 보류됐습니다([EVALUATION.md](EVALUATION.md) '인계 초안'). 되짚기 검사는 과하게 막는 쪽으로 틀립니다: 약 문의(Q25)는 약 말을 쓸 수 없어 되짚기를 쓰기 어렵고, 물음 문장 안의 사실("감기 기운이 있어도 … 가도 되나요?"의 '감기 기운')을 평서로 되짚으면 보류하고, 적신호 증상이 있는 문의는 되짚기에 그 증상을 모두 담아야 합니다. 행정 안내 문단은 물음 절에 의료가 아닌 물음의 말이 있을 때만 가지만, 그 안에서는 점수로 고르므로 묻는 것과 딱 맞지 않는 문단(Q36 경과 진료 일정 물음에 일반 예약 변경 규정)도 갑니다. 직원 문단은 발췌에서 빼지만, 보내는 문단 안에도 직원 문장(V07 '이상하면 연락'의 둘째 문장)과 증상 목록(V11 즉시 조치 문단의 첫 문장)이 있어 모델이 그 문장을 쓰면 코드가 보류합니다. 약·증상 말 목록은 문의 게이트와 같은 값이라 과하게 보류하는 쪽으로 틀리고, 보류되면 직원은 승인 문구만 보내고 의료진이 직접 연락합니다. 지시문이 섞인 문의(Q10)도 이제 초안 모델에 들어갑니다.
- **가상 볼트 문구가 새 동작보다 좁습니다.** V11·V12·V17은 "인계한 뒤 환자에게는 고정 안내 문장만 보낸다"고 적습니다. 직원 동작은 그대로(직원은 그 문장만 보냄)이고 AI 초안은 의료진이 확인해 보내므로 모순은 아니라고 봤습니다. 볼트를 고치면 검색 점수와 4회차 녹화 대조가 흔들려 이번에는 두었고, 실제 도입 때는 간호팀이 의료진 확인 초안 절차를 문서에 더해야 합니다.
- **초안이 볼트 문장을 통째로 옮깁니다.** 인용 대조를 쉽게 하려고 그렇게 지시했습니다.
  - 2회차에서는 직원용 절차 문장("직원은 … 대조한 뒤")이 환자 답장에 섞였습니다. 4회차 전수 1차 검토에서는 Q20의 내규 문장 하나만 남았습니다. 보내기 전에 사람이 읽어야 합니다.
  - 환자 답장에 문장 성분으로 쓰인 링크는 문서 제목("예약·변경·취소·예약금·환불 규정")으로 남아, 환자가 열 수 없는 문서 이름이 나갈 수 있습니다(화면이 알림).
  - 링크가 승인되지 않은 문서(초안·옛 판)나 모르는 파일을 가리키면 환자 답장은 보류합니다.
- **가격 칸은 인용한 원문의 금액과 대조합니다.**
  - 전에는 모델이 가격 키를 잘못 고르면(모당 가격 자리에 수술 예약금 키) 인용·겹침 대조를 통과해 다른 항목 금액이 나갈 수 있었습니다.
  - 지금은 가격 칸이 든 문장은 그 금액이 적힌 문서 문장을 인용해야 합니다. 인용한 원문 문장의 금액과 칸의 값이 다르면 보류합니다(2회차 녹화의 가격 칸 문장 11개는 모두 통과).
  - 인용 없이 가격 칸만 쓴 문장은 받지 않습니다(녹화에는 0개).
- **화면의 보낼 글은 지금 코드로 다시 채운 글입니다.**
  - AI가 쓴 문장은 녹화 그대로이고, 가격·시간 칸과 문서 이름만 지금 볼트와 코드로 넣습니다.
  - 녹화 뒤 가격표 값이 바뀌면 화면의 금액도 바뀝니다. AI는 금액을 쓰지 않았으므로 맞는 동작입니다.
  - 다시 채우지 못하면(가격표 키가 사라지는 등) 보낼 글을 만들지 않고 "AI 답 이후 바뀜"으로 표시합니다.
- **뜻이 뒤집힌 문장은 코드가 못 잡습니다.** "해도 됩니다"와 "하면 안 됩니다"처럼 겹치는 글자가 많은 문장은 인용 대조를 통과할 수 있습니다. 그래서 사람이 보냅니다.
- **근거 없는 질문의 절반 이상은 검색 단계에서 걸러지지 않습니다**(3/8만 멈춤). 녹화에서는 나머지 5개를 모델의 "[근거 없음]"이 막았습니다(8/8).
- **데이터가 전부 합성입니다.** 실제 문의는 더 짧고, 오타가 많고, 사진만 오기도 할 것입니다[추론]. 데이터와 코드를 같은 도구로 만들었습니다.
- **검수 전입니다.** 골든셋 50문항과 문의 라벨은 AI 초안입니다. 적신호 별도 10문장도 아직 쓰지 않았습니다.
- **실제 채널 연결이 없습니다.** 공통 문의 형식만 있고 입력은 합성입니다. 로그인도 없습니다. 승인·발송 기록은 브라우저 저장소에만 남습니다.
- **라이브 모드는 화면에 연결하지 않았습니다.** 키 확인 함수만 있고 모델을 부르는 서버 라우트는 아직 없습니다.
- **시한 해석이 추정입니다.** 병원에 확인할 값입니다.
  - 예약금 확정 연락 '1영업일'을 "다음 진료일 진료 종료까지"로 읽었습니다.
  - 법정 공휴일은 계산에 넣지 않았고, 토요일(오후 3시 종료)도 진료일로 셌습니다.
  - 평일만 센다면 시연의 '시한 지남' 1건(Q41)은 월 19:00까지 9시간 남은 건이 됩니다.
- **볼트의 의료 서술은 의료진 검토를 받지 않았습니다.** 일반적·보수적으로 쓴 가상 예시입니다.
- **사용자는 가정입니다.** 병원 현장 인터뷰나 검증을 하지 않았습니다.
- **법 검토를 대신하지 않습니다.**
  - 실제로 쓰면 건강 정보가 외부 API로 나갑니다. 2026-09-30부터는 증상·약 문의 본문도 가림 뒤 외부 AI(Anthropic)로 나갑니다. 가림은 이름·연락처만 가리고 증상은 그대로 보냅니다(지금은 가상 데이터).
  - 실제 병원 도입 시 민감정보 처리 위탁·고지·동의가 필요합니다. 국외 이전 고지와 보관 정책도 먼저이고, 원내 모델도 검토해야 합니다.
  - AI가 관여한 글을 환자에게 어떻게 알릴지도 정해야 합니다.

## AI와 사람이 나눈 일

이 저장소의 조사·문서·데이터·코드 초안은 **Claude Code가 썼습니다.** 숨기지 않고 나눠 적습니다.

| 구분 | 내용 |
|---|---|
| AI(Claude Code)가 한 것 | 조사 5건, PRD 초안과 적대적 검토(PRD 3건, 화면 1회), 가상 의원 문서·합성 문의·골든셋 초안, 코드와 테스트 초안, 커밋 메시지, 녹화 초안의 1차 판정 |

| 아직 할 것 | PRD 7절 기준 최종 확인, 모델 최종 결정(비용은 쟀음), 골든셋 검수, 적신호 별도 10문장 작성, 녹화 초안 판정 검토(AI 1차 판정만 있음) |
