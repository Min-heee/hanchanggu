# 한창구 PRD

> 이 문서는 **구현을 시작하기 전에** 썼습니다(v0.1이 저장소의 첫 커밋입니다). "여러 창구의 문의를 한 번에 보고 답장하는 도구"는 제 아이디어이고, "AI 업무 코파일럿"이라는 틀과 ①검색 → ②발췌 → ③생성 → ④근거 표시 단계 표현은 제가 다른 AI 대화에서 가져온 것입니다. 초안은 Claude Code가 조사 5건을 바탕으로 썼고, 채택 여부와 7절 기준값은 제 몫입니다. 확인한 사실에는 근거를, 추론에는 [추론]을, 확인하지 못한 것에는 "미확인"을 붙였습니다.

## 1. 한 줄 정의와 문제

**한창구는 병원의 여러 문의 창구에서 들어온 문의를 직원이 보는 화면 하나에 모으고, 병원이 승인한 문서만 근거로 답장 초안을 만들어 직원이 검토한 뒤 보내게 하는 AI 업무 코파일럿입니다. 같은 문서와 같은 엔진으로 직원의 내부 질문에도 근거를 달아 답합니다.**

동네 의원도 문의 창구가 많습니다. 메신저(카카오톡 채널, 네이버 톡톡, 인스타그램 DM), 홈페이지 폼, 예약 요청사항, 전화·문자, 공개 리뷰와 영상 댓글이 흔합니다. 모발 치료처럼 수술 뒤 1년 가까이 관리하는 진료는 같은 환자가 여러 창구로 여러 번 묻습니다. 여기서 세 가지 문제가 생깁니다[추론].

1. **놓칩니다.** 창구마다 따로 열어 봐야 해서 쉬는 날과 밤사이 쌓인 문의 중 무엇이 먼저인지 알기 어렵습니다. 예약금을 받고 확정 연락을 못 한 건은 돈과 평판에 바로 닿습니다.
2. **같은 답을 매번 새로 씁니다.** 수술 후 며칠째 무엇을 해도 되는지, 가격, 예약 변경 규정처럼 답은 병원 문서에 이미 있지만 사람이 찾아서 옮겨 적습니다.
3. **답하면 안 되는 문의가 섞여 있습니다.** "수술 9일째인데 고름이 나와요", "약을 두 알 먹어도 돼요?" 같은 문의에 비의료인이 판단해 답하면 위험합니다.

한창구는 이 셋을 한 화면에서 다룹니다. 목록이 순서를 정하고, 적신호와 의료 판단 질문은 AI보다 규칙이 먼저 잡아 의료진에게 넘기고, 나머지는 병원 문서의 어느 문장을 근거로 썼는지 보이는 초안으로 만듭니다. 보내는 것은 사람입니다.

## 2. 목표와 이번 범위

### 목표

- 여러 창구의 문의를 창구 배지, 받은 시각, 기다린 시간, 상태(새 문의 / 초안 / 인계 / 보류 / 발송)와 함께 한 목록에 보인다.
- 예약금은 받았는데 확정 연락을 못 한 건을 시한과 함께 목록 위로 올린다.
- 문의에서 "수술 9일째" 같은 경과일을 읽어 그 시점의 안내 문단을 먼저 찾는다.
- 적신호와 의료 판단 질문은 LLM보다 앞선 규칙이 먼저 잡아 의료진 인계 카드로 넘긴다. 애매하면 인계한다.
- 답장 초안은 **①검색 → ②발췌 → ③생성 → ④근거 표시** 네 단계를 화면에 그대로 보여 주고, 문장마다 병원 문서의 원문 위치를 단다.
- 같은 엔진으로 직원의 내부 질문에 답하고, 근거가 없는 질문은 '문서 빈칸'으로 모아 문서를 채울 곳을 알려 준다.
- API 키 없이 링크 하나로 30초 안에 핵심 장면을 본다(3절).

### 이번 범위에서 하지 않는 것

- **진단, 치료 판단, 약 용량, 효과 보장, 탈모 단계 판정.** 생성하지 않고 인계합니다.
- **실제 채널 연결.** 메신저는 병원이 이미 쓰는 상담 도구가 받아 웹훅으로 넘겨 주는 구조를 전제로, 공통 어댑터 형식만 만들고 입력은 합성 데이터로 합니다(6절).
- 자동 발송, 창구가 다른 사람을 같은 환자로 자동 병합하기, 진료기록 연동, 로그인.

## 3. 사용자와 30초 시연

**30초 시연(처음 보는 사람, 노트북, API 키 없음).** 시연 모드의 기준 시각은 월요일 오전 10시로 고정합니다.

| 초 | 장면 |
|---|---|
| 0~5 | 목록: 금요일 오후부터 주말을 지나 월요일 아침까지 쌓인 문의 41건이 창구와 상관없이 한 줄로. 맨 위 빨간 칸은 적신호·약 문의 인계, 그 아래 주황 칸 맨 앞에 빨간 배지 "예약금 받음 · 확정 연락 시한 1일 19시간 지남"(금요일 오후에 받아 토요일 진료 종료가 시한이었던 건) |
| 5~12 | 가격 문의를 열면 초안이 있고 문장마다 번호가 붙어 있다. 번호를 누르면 원문 문단이 칠해진다. 가격은 AI가 쓴 숫자가 아니라 가격표에서 들어온 값이다 |
| 12~20 | **직접 해 보기:** 보는 사람이 입력창에 "이식한 지 열흘인데 부위가 뜨겁고 누르면 아파요"를 치면 키 없이도 규칙이 바로 인계 카드를 띄운다(걸린 규칙, 담당, 응답 시한, 환자에게 보낼 승인 문구) |
| 20~26 | 사내 Q&A: "수술 3일째 환자가 머리를 감아도 되냐고 물으면 뭐라고 해요?"(골든셋 G16, 화면 맨 위 버튼) → ①~④ 단계가 차례로 열린다. 근거 없는 질문("대기실 와이파이 비밀번호가 뭐예요?", G38)은 '문서 빈칸'으로 간다 |
| 26~30 | 평가 탭: 적신호 누락, 검색 적중률, 보류 정확도와 틀린 사례 |

화면에는 "가상 의원 · 합성 데이터"와 AI 초안이 미리 만든 것인지(모델·생성일), 아직 준비 전인지가 항상 보입니다. 규칙 게이트와 검색은 브라우저에서 바로 돌고, AI 생성 결과만 미리 만들어 둔 것입니다.

**사용자 A — CS 직원.** 위 목록에서 일합니다. 초안을 고치고 승인하면 발송 기록이 남습니다.
**사용자 B — 원장·간호.** 인계 카드에서 원문, 걸린 규칙, 환자가 적은 경과일을 보고 직접 연락합니다. 한창구는 증상을 해석하지 않습니다.
**사용자 C — 신입 직원.** 사내 Q&A로 병원 문서를 찾습니다.

A~C는 가정한 사용자입니다. 병원 현장 인터뷰나 검증은 하지 않았습니다.

## 4. 요구사항

| ID | 무엇을 | 완료 기준 |
|---|---|---|
| F1 | 합성 데이터: 가상 의원 '샘플의원'의 문서 볼트(Obsidian에서 바로 열리는 md, 프런트매터에 유형·버전·승인 상태·시행일), 합성 문의 41건, 골든셋 50문항 | 볼트를 Obsidian으로 열면 링크가 이어진다. 골든셋 문항마다 정답 문서와 보류·인계 여부가 있고, 사람 검수 여부가 표시된다 |
| F2 | 창구 어댑터: 공통 문의 형식(창구, 외부 ID, 받은 시각, 가명, 본문, 첨부 메타, 답장 방식: 직접 / 복사 / 전화 / 고정 문구만) | 창구별 답장 방식이 데이터로 있고 발송 버튼이 그 방식을 따른다 |
| F3 | 통합 목록 | 적신호 → 약·분류 인계 → 확정 대기 → 기다린 시간 순. 창구·유형·상태로 거를 수 있다 |
| F4 | 분류(유형·우선순위) | 분류마다 근거 표현이 붙는다. 실패하면 "미분류"로 두고 초안을 만들지 않는다 |
| F5 | 적신호·의료 판단 게이트 | 규칙이 LLM보다 먼저 돈다. 증상어·경과 문맥·약 관련 표현 목록은 볼트 문서에서 읽는다(코드에 하드코딩하지 않음). 목록이 비거나 깨지면 전부 인계한다. LLM은 인계 쪽으로만 바꿀 수 있다 |
| F6 | 인계 카드 | 걸린 규칙, 담당 역할, 응답 시한, 시한이 지나면 다시 경보, 환자에게 보낼 문구는 볼트에 있는 승인 문구만 |
| F7 | ①검색·②발췌 | 한국어 문자 2-gram BM25로 문단 단위 검색. 승인된 최신판만 대상이고, 제외된 문서(초안, 옛 판)는 "제외됨"으로 보인다. 점수가 기준 미만이면 모델을 부르지 않고 보류 |
| F8 | ③생성·④근거 | Claude API의 문서 인용(citations)으로 생성한다. 인용 원문이 볼트 문단과 실제로 같은지, 문장 속 숫자·기간이 인용 원문에 있는지 코드가 대조하고, 어긋나면 초안 전체를 보류한다. 인사·맺음말을 뺀 무인용 문장은 막는다. 인용 문장이 하나도 없는 초안(인사·맺음뿐)과, 인용 밖 짧은 이음말에 숨긴 가능 여부·날짜·기호·한글로 쓴 수도 막는다 |
| F9 | 가격·진료시간 칸 | 모델에는 금액을 주지 않고 자리표시자만 쓰게 한다. 코드가 볼트 가격표에서 값을 넣는다. 넣은 뒤에도 모델이 쓴 금액 패턴이 남으면 보류한다 |
| F10 | 개인정보 가림 | 전화·이메일·주민번호·생년월일·"○○님/씨" 호칭·폼의 이름·주소 칸을 모델 호출 전에 가리고, "모델이 실제로 받은 텍스트"를 화면에서 볼 수 있다 |
| F11 | 공개 창구 규칙 | 리뷰·댓글에는 치료 내용과 환자임을 드러내지 않는 고정 문구만 제안한다 |
| F12 | 광고 표현 검토 신호 | 효과 보장, 최고·100%, 할인 유인, 후기 대가 표현에 경고를 띄운다. 적법성 판정이 아니라 사람이 다시 볼 신호다 |
| F13 | 승인·발송(모의)·기록 | 누가 어떤 문장을 고쳤는지 남는다. 실제 전송은 없다 |
| F14 | 사내 Q&A와 문서 빈칸 | 문의 초안과 같은 엔진. 근거 없는 질문은 빈칸 목록에 쌓여 주간 보고로 볼 수 있다 |
| F15 | 평가 탭 | 7절 지표와 틀린 사례 목록 |
| F16 | 예약 확정 대기 | 예약금 받음·미확정 건에 확정 연락 시한을 붙여 목록 위로 올린다. 직원이 연락 시도를 체크하고, 확정·일정 변경·환불 안내 초안은 예약 규정 문서를 근거로 만든다 |
| F17 | 경과일 읽기 | 문의의 "N일째", "열흘", "D+N"을 숫자로 읽어 그 구간의 안내 문단을 검색 결과 앞에 둔다. 읽은 값은 카드에 표시하고, 직원이 고칠 수 있다 |
| F18 | 시연 모드와 라이브 모드 | 시연 모드는 기준 시각 고정, 미리 생성한 응답(모델명·생성일 표시)만 쓰고 방문자 비용이 0이다. 공개 배포에는 API 키를 두지 않는다. 라이브 모드는 로컬에서 키가 있을 때만 켠다 |

**자르지 않는 것:** F5·F6(적신호), F8(인용 검증), F9(가격 칸), F11(공개 창구), F16·F17, 시연 모드. **자르는 순서:** 라이브 모드 → 사내 Q&A 화면 분리 → 수정 이력 세부 → 평가 탭 화면(숫자는 README로).

## 5. 처리 경로

| 문의 유형 | 경로 |
|---|---|
| 증상·경과 불안(사진 포함) | 인계 카드 |
| 약·용량·복용 중단 | 인계 카드 |
| 견적·필요한 모발 수 | 상담 예약 안내 초안(수치 답 없음) |
| 가격·진료시간 | 초안 + 가격·시간 칸 |
| 예약·변경·취소·환불 | 초안(예약 규정 근거), 예약금 건은 확정 대기 |
| 수술 후 일정·관리 | 경과일 구간 안내 초안(승인 안내문 원문 전달까지만) |
| 리뷰·댓글 | 고정 문구 |
| 쇼핑몰 상품 | 목록에 모으지 않고 연결 창구만 안내(운영 주체가 다를 수 있음) |

```
문의 → 가림(F10) → 게이트(F5) ─┬─ 인계 카드(F6)
                               ├─ 공개 창구 → 고정 문구(F11)
                               └─ 분류(F4) → 경과일(F17) → ①검색 → ②발췌 → ③생성 → ④근거·검증(F8, F9, F12) → 직원 승인(F13)
```

검색은 임베딩 없이 BM25로 시작합니다. 문서 20편, 문단 수백 개 규모이고 "D+3", "모당"처럼 정확히 맞아야 하는 용어가 많으며, 결과를 사람이 설명할 수 있습니다. 문서가 수천 편으로 늘면 임베딩을 섞습니다. 인용은 프롬프트로 부탁하지 않고 API 기능으로 받아 코드가 검증합니다. 이 기능은 구조화 출력과 한 호출에 함께 쓸 수 없어서 분류와 생성은 따로 부릅니다. 문의 원문은 시스템 지시와 분리된 데이터로만 넘기고, 지시문이 섞인 문의를 적대 케이스에 넣습니다.

| 예약 요청사항 | 공개 API 없음, 알림 메일(내용 범위 미확인) | 불가 |
| 리뷰·블로그 | 공개 API 없음 | 불가 |
| 영상 댓글 | 공식 API(본인 채널) | 가능 |

**상담 도구와의 관계.** 메신저를 한곳에 받는 일은 채널톡 같은 상담 도구가 이미 잘합니다. 한창구는 그 도구가 받은 메신저 문의를 웹훅으로 넘겨받고, 그 도구가 받지 못하는 창구(예약 요청사항, 폼, 리뷰, 댓글)를 더해 **직원이 보는 화면을 하나로** 만듭니다. 그 위에 병원 규칙(적신호 인계, 승인 문서 근거, 가격 칸, 확정 대기, 경과일)을 얹습니다. 상용 AI 상담처럼 환자가 AI와 직접 대화하지 않고, 직원이 검토한 글만 나갑니다. 어댑터는 특정 도구에 묶이지 않습니다.

**자동화를 넓히는 길.** 지금은 모든 초안을 사람이 승인합니다. 운영하면서 유형별로 "고치지 않고 보낸 비율"을 재고, 그 비율이 높고 위험이 낮은 유형(진료시간, 위치)부터 자동 발송을 병원과 함께 검토할 수 있습니다. 증상·약·환불은 계속 사람이 봅니다.

**같은 사람을 자동으로 합치지 않는 이유.** 잘못 합치면 다른 환자의 치료 정보가 초안에 들어가 그대로 유출됩니다. 경과일은 환자가 문의에 쓴 문장에서 읽거나 직원이 입력한 값만 씁니다.

**합성 데이터.** 문의에는 증상과 사진 같은 건강 정보가 섞여 있어 민감정보일 가능성이 높습니다[추론]. 저장소와 시연에는 가상 의원 문서와 합성 문의만 넣고, 실제 후기·대화를 바꿔 쓴 문장도 넣지 않습니다. 볼트의 의료 서술은 일반적·보수적으로 쓴 가상 예시이고 의료진 검토를 받지 않았습니다.

**스택.** Next.js 15(App Router, 서버 라우트), TypeScript, `@anthropic-ai/sdk`, vitest, Vercel. 데이터베이스 없이 저장소의 JSON과 마크다운으로 충분한 규모입니다. 모델은 `claude-sonnet-5-5`이고, 거절 시 서버 측 대체 모델을 켭니다. `claude-opus-5`로 시작했지만 녹화 비용을 추정해 보니(전체 1회 약 $10~15) 이 규모에 비해 커서, 단가가 2.5배 낮은 Sonnet 5.5로 제가 바꿨습니다(2026-09-29). 실제 비용은 녹화로 쟀습니다. 전체 녹화 1회에 1회차 $0.55, 2회차 $0.56, 3회차 $0.70, 4회차 $0.73입니다([docs/EVALUATION.md](EVALUATION.md)).

## 7. 평가

## 9. 도입한다면

**첫 2주.** 1주차에는 병원 문서(인계장, 안내문, 가격표)를 볼트로 옮기고 적신호·약 표현 목록을 의료진과 함께 고칩니다. 2주차에는 실제 문의를 한창구에 넣되 발송은 기존 방식대로 하고, 초안과 실제 답을 나란히 비교합니다.

**병원에 묻고 싶은 것.**
1. 문의가 가장 많이 쌓이는 창구와 시간대는 어디인가요?
2. 예약금 확정 연락은 지금 누가, 어떤 순서로 하나요?
3. 증상 문의는 누구에게, 몇 분 안에 넘어가야 하나요?
4. 지금 쓰거나 고르고 있는 상담 도구가 있나요?
5. 예약금 확정 연락의 '1영업일'에 토요일(오후 3시 종료)을 세나요?

## 10. 리스크와 일정

- **외부 API로 건강 정보가 나간다.** 실제로 쓴다면 가림만으로는 부족합니다. 처리 위탁·국외 이전 고지와 동의, 학습 미사용 설정, 보관 기간 정책이 먼저이고, 민감한 문의는 원내 모델로 처리하는 대안도 검토해야 합니다. 이 데모는 그 검토를 대신하지 않으며 법률 자문이 아닙니다.
- **AI 관여 고지.** 고객에게 나가는 글에 AI가 관여했다는 사실을 어떻게 알릴지는 병원 정책과 법 검토가 필요합니다. 데모 화면에는 "AI 초안, 사람이 검토 후 발송"을 항상 표시합니다.
- **환각과 뜻 뒤집힘.** 인용 대조, 숫자 대조, 무인용 문장 차단, 가격 칸으로 줄이지만 "해도 됩니다"와 "하면 안 됩니다"처럼 겹치는 글자로 뜻이 바뀌는 문장, 인용 문장과 반대인 "네,"·"아니요," 머리말은 코드가 잡지 못합니다. 그래서 사람이 보냅니다.
- **과잉 인계.** 애매하면 인계하는 설계라 실제 문의에서는 인계가 많을 수 있습니다. 도입 2주차 비교로 목록을 고칩니다.
